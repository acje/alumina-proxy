**Working description:**
The DoT client genuinely offers TLS 1.2 + 1.3 via
`with_safe_default_protocol_versions` (`startup_dns.rs:827-828`) with the
`tls12` feature kept (`Cargo.toml:201`). The spec's TLS 1.3-only clauses

code comment, not the byte-canonical spec. **Spec deviation:** yes — spec is
silent on the outbound client TLS profile while the code offers 1.2+1.3.
**Fix target: spec** (document the client-surface TLS profile).

## G2-C09 — Info — `dp=` downgrade counter misses failback-begin relocation

**Scorecard row:**
```
| G2-C09 | Medium→Info | src/startup_dns.rs:2585-2606 | code\|spec | `dp=` downgrade counter misses failback-begin relocation (maybe_begin_failback → primary) — real DoT→plain relocation uncounted; spec :774 enumerates only two on_exchange_failed choke points. Cross-ref G1-C09 (same root). |
```

**Working description:**
`maybe_begin_failback` (`startup_dns.rs:2585-2606`, relocation at `:2601`) is
the only one of the four relocation paths that never calls
`note_downgrade_if_dot_to_plain`. When the backup is a DoT `IP#fqdn` entry and
the primary is bare-IP plain, a failback-begin move is a genuine DoT→plain
serving relocation that matches the counter's own downgrade condition but is
uncounted — the only counted sites are the two `on_exchange_failed` choke
points (spec `:774`) plus the separately-blessed probe sweep (`:829`/`:2700`).
No test covers it. **Spec deviation:** yes — spec `:774` enumeration would need
amendment to include failback-begin relocation. **Fix target: code|spec**.
Severity normalized to **Info** (observability-only; no security/data-path
impact).

**Cross-group:** duplicate family with **G1-C09** (primary) and **G6-C01** —
merged at aggregation; G4-C05 (DISCARD) is the config-layer complement.
