## G1-C03 — Info — dead `earliest == u64::MAX → 1` fallback in positive-outcome TTL computation

**Scorecard row:**
```
| G1-C03 | Info | src/dns.rs (earliest==u64::MAX→1) | code | Dead `earliest == u64::MAX → 1` fallback in positive-outcome TTL computation |
```

**Working description:**
`if earliest == u64::MAX { 1 }` at `src/dns.rs:1095-1097` is genuinely
unreachable: `!bindings.is_empty()` guarantees the min-loop folds in at least
one real `u32` addr TTL (`< u64::MAX`). The TTL-0→1 rule the guard implies is
actually enforced at `cache.rs:328` (`clamp(1, TTL_CAP)`) per spec `:74`.
Misleading dead guard; no spec deviation (rule enforced elsewhere). **Fix
target: code** (remove or comment the dead guard).

## G1-C07 — Info — `Fqdn::parse` rejects all-numeric final label (undocumented validation rule)

**Scorecard row:**
```
| G1-C07 | Medium→Info | src/resolver.rs:72-78 | code | `Fqdn::parse` rejects all-numeric final label (undocumented validation rule) |
```

**Working description:**
`resolver::Fqdn::parse` (`resolver.rs:72-78`) rejects all-numeric final labels
(`foo.123`, `123`), diverging from `config::Fqdn` which accepts `foo.123` (only
rejects whole-name IP-literal shape). The rule is undocumented: spec `:626`
(V37) claims the resolver rule "matches" `config::Fqdn` and documents only
"digit-leading labels allowed". Reachable via `IP#fqdn` resolver endpoints.
Fails closed with a clear startup error; no real all-numeric TLDs exist, so
voters rate **Info** (not manifest Medium). **Spec deviation:** yes — spec
`:626` claims parity with `config::Fqdn` that the resolver does not implement.
**Fix target: code** (align resolver rule with config, or document the
divergence).

## G1-C09 — Info — DoT→plain downgrade counter misses failback-begin relocation

**Scorecard row:**
```
| G1-C09 | Info | src/startup_dns.rs:2585-2606, :2612-2626 | spec | DoT→plain downgrade counter scope: config-form downgrade counted, failback relocation not counted (dotdg amendment needed) |
```

**Working description:**
`maybe_begin_failback` (`startup_dns.rs:2585-2606`) relocates the DoT backup →
bare-IP primary without calling `note_downgrade_if_dot_to_plain` — only the
probe (`:2700`), re-seat, and failover (`:2757`/`:2769`) sites count. In a
plain-primary + DoT-backup config, the failback-begin DoT→plain transition
matches the `dotdg` amendment's own downgrade predicate
(`docs/alumina-proxy.md:774`) yet is uncounted — an inconsistent scope gap.
**Spec deviation:** yes — spec `:774` scopes the counter to the two
`on_exchange_failed` choke points only, undercutting the `:770` intent to
"surface the failover downgrade path". **Fix target: spec** (extend the `dotdg`
amendment scope to failback-begin relocation).

**Cross-group:** duplicate family with **G2-C09** and **G6-C01** (same
`dp=` downgrade-counter gap) — merged here; G4-C05 (DISCARD) is the
config-layer complement.
